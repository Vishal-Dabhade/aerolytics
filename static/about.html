The problem

An engine's remaining useful life (RUL) is how many more flight cycles it can run before it fails or must be taken out of service. If maintenance happens too early, useful life is thrown away. If it happens too late, a fault can become a failure. Predictive maintenance tries to estimate RUL from the sensor data an engine already produces, so that work can be scheduled at the right time.

This project predicts RUL from one reading or from a history of readings, using three standard models: Linear Regression, Random Forest and XGBoost.

The dataset

The data is NASA's C-MAPSS turbofan degradation simulation, subset FD001. It has 100 training engines recorded from a healthy state until they fail (20,631 rows), and 100 test engines whose records stop before failure (13,096 rows). A separate file gives the true remaining life of each test engine at its last recorded cycle.

Each row is one flight cycle of one engine, with three operating settings and 21 sensor readings. FD001 has a single operating condition and a single fault type, which makes it the simplest of the four C-MAPSS subsets. Explore it in the dataset explorer.

Data preparation

Eight columns never change in FD001 (setting_3 and sensors 1, 5, 6, 10, 16, 18 and 19), so they carry no information and were dropped. That leaves two settings and 14 sensors. Each sensor also gets a rolling average of its last three cycles, which smooths random noise and gives a single row a little memory. The cycle number is also an input. All inputs were scaled using the training data only.

The capped target

While an engine is healthy, its sensors look almost the same whether it has 300 cycles left or 150. Asking the models to separate those cases only teaches them noise. So for training, remaining life above 125 cycles is set to 125. The test scores are always computed against the actual remaining life, never the capped value. The cost is that predictions never exceed 125, which the app shows as 125+.

Validation by engine

Neighbouring cycles of one engine look almost identical. If they were split randomly between training and validation, the models would be tested on near copies of what they trained on and look better than they are. So cross-validation uses five folds that hold out whole engines. Every design choice, including the cap, the rolling window, the cycle number and the tuning settings, was decided with these validation scores.

Model selection and final test

After the choices were fixed, the three models were retrained on all 100 training engines and scored once on the 100 test engines, using each engine's last recorded cycle and its actual remaining life. Random Forest had the lowest error, with XGBoost close behind and Linear Regression clearly behind. See the full results and how the models were built.

Limitations

The data is simulated. Real engines have different noise, missing data, many operating conditions and several ways of failing. FD001 covers one condition and one fault, so these models should not be expected to carry over to other cases without retraining.

The estimates are rough. On unseen test engines the best model is off by about 14 cycles on average and by 19 in RMSE terms, and a few engines are off by more than 40. Treat each prediction as a range, not a date.

The cycle number is an input. It improved validation error, but it means the models partly use an engine's age, not only its condition.

Single readings are approximate. The models were built around a three-cycle rolling average. A single manual entry uses its own value as that average, so it can differ a little from the exact calculation. Upload three or more cycles for the exact result.

Edited readings are not forecasts. The sliders can combine values that no real engine would produce. Those results show how the model reacts to numbers, not what an engine will do.

Small test set. One hundred engines is enough to rank the models, but small differences between Random Forest and XGBoost should not be over-read.

This is a study of the method. It is not a certified maintenance tool and should not be used to make safety decisions.
